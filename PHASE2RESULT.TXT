1. REAL HARDWARE INPUT & OUTPUT ROUTING IMPLEMENTATION
--------------------------------------------------------------------------------
• Service Architecture:
  - Implemented `AudioRoutingManager` (package com.example.audio.routing).
  - Encapsulates Android's modern audio routing APIs for API 31+ (Android 12, 13, 14, 15, 16).
  - Interacts directly with `android.media.AudioManager.setCommunicationDevice(AudioDeviceInfo)`.
  - Clears routes via `android.media.AudioManager.clearCommunicationDevice()`.
  - Manages audio modes canonically: sets `AudioManager.MODE_IN_COMMUNICATION` when routing communication audio, and restores `AudioManager.MODE_NORMAL` when reverting to system default.

• Route Verification & Robustness:
  - Pre-flight check: verifies candidate device is registered with Android audio HAL.
  - Post-flight verification: inspects `audioManager.communicationDevice` to verify device assignment.
  - Disconnect Handling: if an active routed device is unplugged or disconnected, `AudioRoutingManager` cleanly resets the route and restores the default speaker.
  - Rejection Reporting: if Android rejects a route (e.g. unsupported OEM audio profile or unavailable hardware endpoint), a clean dismissable alert informs the user ("Unable to use this audio device. Android rejected the requested audio route.").

• Independent Input & Output Separation:
  - Output routing (e.g., Phone Speaker, Bluetooth Earbuds, USB DAC, Wired Headphones) operates independently of input routing.
  - Input routing (e.g., Phone Microphone, Headset Mic, Bluetooth Mic) operates without disturbing or resetting output channels.
  - State is tracked with dedicated flows in `MainViewModel` (`userSelectedOutput`, `userSelectedInput`, `activeOutputDevice`, `activeInputDevice`).
